### Product: **"פורחים" (Bloom) — גינת ריכוז אישית**

Problem: studying alone at home, nobody notices when you drift, and a number on a screen doesn't
motivate anyone. Bloom turns focus into something you grow and care about: **every study session
plants a seed, and it only grows while you are actually focused.** (Nothing like this existed in
the original FocusFlow, which was about generated questions, summaries, playlists and groups — do
NOT build quizzes, summaries or playlists.)

Core features (on top of the base):

1. **Live plant** — on the watch/read screen, next to the content, an animated SVG plant
(seed → sprout → leaves → bud → flower). It grows a step for every \~2 focused minutes
(score ≥ 0.5), stays still at 0.4–0.5, and droops gently when score < 0.4. The base score
(number + colored bar) stays visible under it — the plant is extra, not a replacement.
2. **Low-focus reaction** — score < 0.4 for \~15 s → banner "הצמח שלך צמא לריכוז 🌱" + the plant droops;
for YouTube, optional auto-pause (user toggle). Recovering focus revives it with a small animation.
No face → "לא זוהו פנים", plant "sleeps" (does not die), nothing is sent.
3. **My garden ("הגינה שלי")** — after "סיים סשן" the plant is planted in a garden grid (the history
screen, styled as a garden; still also shows a plain list: date, content title, average score).
Plant species is chosen by content type (YouTube = sunflower, text = fern, web = cactus), height
by focused minutes, flower color by average score. Click a plant → the session details: chart of
score over time + readings.
4. **Beds = subjects ("ערוגות")** — content items get an optional `bed` (subject, e.g. "היסטוריה");
the garden is grouped into beds; each bed shows total focused minutes and average.
5. **Earned breaks** — every full bloom (≈25 focused minutes) unlocks a 5-minute break with a
countdown ("הרווחת הפסקה"), the camera is turned off during the break.
6. **Garden journal ("יומן הגינה")** — insights page: focused minutes per day (last 14 days),
best hour of the day, average by bed, streak of days with ≥ 1 flower, and per-session strip of
v4\_2 `attention\\\_weights` ("which seconds counted most"). Short Hebrew tips generated by rules.
7. **Seasons \& badges** — small rule-based achievements ("פרח ראשון", "שבוע ירוק", "ערוגה מלאה").
8. **Shared garden — study buddy ("לומדים ביחד")** ⭐ the signature feature. Build it LAST, only
after the base and features 1–7 pass verification; it must never break or block a solo session.

   * On the watch screen: button "הזמן חבר ללמוד איתך" → creates a study room with a 6-character
code + share link (`/room/ABC123`). The friend logs in (own account), opens the link, picks
their own content (can be different), and starts their own normal session inside the room.
   * Each participant sees, beside their own plant, the friend's plant + display name growing or
drooping live, plus a status: "מרוכז/ת", "צריך/ה עידוד", "לא מול המצלמה", "בהפסקה".
A "שלח עידוד 🌞" button shows a small sun animation on the friend's screen.
   * When both reach full bloom → shared badge "פרחנו ביחד" and a joint plant appears in both gardens.
   * Privacy: explicit opt-in text before joining ("רק שם התצוגה, ציון הריכוז ושלב הצמח משותפים —
בלי וידאו ובלי נקודות פנים"). Only members of the room can read it (403/404 otherwise). Leave
button. Room expires after 4 h of inactivity (Mongo TTL index). Max 4 members.
   * Transport: **short polling every 3 s** (`GET /api/rooms/{code}`), state kept in Mongo — works
with several Cloud Run instances behind the Load Balancer without sticky sessions. (WebSocket
is optional and only if it also works with ≥ 2 instances; explain the choice in EXPLAIN.md.)
   * API: `POST /api/rooms` → code · `POST /api/rooms/{code}/join` · `POST /api/rooms/{code}/leave` ·
`GET /api/rooms/{code}` → members \[{display\_name, stage, last\_score, status, updated\_at}] ·
`POST /api/rooms/{code}/cheer`. The member's stage/score is updated server-side whenever their
session gets a reading (session has optional `room\\\_code`).
   * Verify with Playwright: two browser contexts, two users, two fake cameras (face video + no-face
video) → each sees the other's status change within \~5 s; a third user without joining gets 404.

Extra API (document in PROJECT\_INFO `changes\\\_to\\\_recommended\\\_api` as *additions only*):
`GET /api/garden` (plants derived from ended sessions), `GET /api/journal`, `GET /api/badges`, `/api/rooms/...` (feature 8),
optional `bed` field on content. Plant stage is computed from readings on the server — not trusted from the client.

## 1\. Fixed requirements (must not deviate)

* Server: **Python + FastAPI**, port **8000**, `GET /health` → `200 {"status":"ok"}` (exact path, no `/api`).
* Client: **React + Vite** (TypeScript ok), served on port **3000**.
* DB: **MongoDB** container with a named volume. Server connects via `MONGODB\\\_URI=mongodb://mongo:27017` (service name, not localhost), `DB\\\_NAME=focusflow`.
* One `docker-compose.yml`, `docker compose up` starts everything, no manual steps.
* Compose uses **public images** (`image:` from Docker Hub/GHCR), **built for `linux/amd64`**
(`docker buildx build --platform linux/amd64 --push`). Model files are **baked into the client image**. No `build:` needed at grading time.
* Client calls the API **same-origin, relative paths** (`/api/...`). The client container is nginx that
serves the build AND proxies `/api/` and `/health` to `${BACKEND\\\_URL}` (nginx envsubst template;
in compose `BACKEND\\\_URL=http://server:8000`). This way the **same image** works locally and in the
cloud (where the Load Balancer routes `/api/\\\*` to the server before it ever reaches nginx). Server
still also exposes port 8000 directly. nginx must listen on `${PORT:-3000}`.
* The server must be **stateless** (everything in Mongo, nothing in Python dicts) — Assignment 4 runs ≥ 2 instances.
* `.env` contains `MONGODB\\\_URI`, `DB\\\_NAME`, `JWT\\\_SECRET` (random), `GEMINI\\\_API\\\_KEY=` **empty**. Site must work and fail politely without Gemini.
* No real secrets anywhere in code/images/GitHub; `.env` in `.gitignore`.

## 2\. API (all JSON, all under `/api` except `/health`)

Errors: always `{"detail": "message"}` — 400 bad request, 401 not logged in, 404 not found, 409 conflict, 422 invalid input.
Times: ISO 8601 UTC strings. IDs: strings.

|Route|Auth|Body|Response|
|-|-|-|-|
|GET /health|open|—|200 `{"status":"ok"}`|
|POST /api/auth/register|open|email, password, display\_name|201 id,email,display\_name · 409 email exists · 422 invalid (email case-insensitive unique, password ≥ 8)|
|POST /api/auth/login|open|email, password|200 access\_token, token\_type:"bearer", expires\_in (s) · 401|
|POST /api/auth/logout|auth|—|204|
|GET /api/users/me|auth|—|200 id,email,display\_name,created\_at|
|PATCH /api/users/me|auth|display\_name|200 user|
|POST /api/users/me/password|auth|current\_password,new\_password|204 · 400 wrong current|
|DELETE /api/users/me|auth|—|204, deletes all user data (content, sessions, readings)|
|POST /api/content|auth|type (`youtube`/`text`/`web`), title, source|201 id,type,title,source,created\_at · 422|
|GET /api/content|auth|—|200 list of own items|
|GET /api/content/{id}|auth|—|200 · **404 if missing OR other user's**|
|DELETE /api/content/{id}|auth|—|204|
|POST /api/sessions|auth|content\_id|201 id,content\_id,started\_at|
|POST /api/sessions/{id}/readings|auth|position (sec / text offset), score (0–1)|201 position,score,created\_at · 422 · 409 if session ended|
|POST /api/sessions/{id}/end|auth|—|200 id,started\_at,ended\_at,reading\_count,average\_score|
|GET /api/sessions|auth|—|200 list with content\_id, average\_score (+ content title)|
|GET /api/sessions/{id}|auth|—|200 summary + readings\[] (score, position, created\_at)|

Security: passwords hashed with **bcrypt** (passlib/bcrypt), never returned or logged. **JWT HS256** signed with `JWT\\\_SECRET`, 60 min expiry, `Authorization: Bearer`. Logout = token added to a denylist (jti) in Mongo with TTL index. Password change invalidates older tokens (store `token\\\_version`/`password\\\_changed\\\_at` and check `iat`). Every query filters by `user\\\_id` taken **from the token**, never from the body. Pydantic validation (EmailStr, URL validation for youtube/web, length limits). Login rate limiting (e.g. 5 failures / 15 min per email+IP → 429). CORS limited to `http://localhost:3000`.

Collections: `users`, `content`, `sessions`, `readings` (or readings embedded in session), `token\\\_denylist`.

## 3\. Model (runs in the browser)

* `@mediapipe/tasks-vision` **FaceLandmarker** → 478 landmarks (x,y,z), raw normalized values, no extra processing. Load wasm + `face\\\_landmarker.task` from files bundled into the image (don't depend on CDN at runtime if possible).
* Sample **10 fps**, keep a rolling window of **100 frames** (10 s).
* Every \~3 s (once window is full) run `onnxruntime-web` on `/models/v4\\\_2.onnx`:

  * input name **`input\\\_x`**, tensor float32 `\\\[1,100,478,3]`
  * outputs: **`regression\\\_scores` \[1,1]** (score 0–1, the main one), `classification\\\_logits` \[1,5] (not-present / not / low / engaged / very engaged), `attention\\\_weights` \[1,100] (use for "which moments mattered" in analytics).
  * Use `session.inputNames\\\[0]` / `outputNames` dynamically anyway (v1–v3 use `input`/`output`).
* Interpretation: \~0.05 not in frame, 0.30 not engaged, 0.50 low, 0.70 engaged, 0.95 very engaged.
* No face in frame → show "לא זוהו פנים", don't run the model, keep going (no crash). Must work with any camera including a virtual one (OBS); allow choosing the camera from a dropdown, default = first.
* First score within \~10–13 s. Then POST each score + position to `/readings`.
* Score display: big number + colored bar (red <0.4, yellow <0.7, green). Score < 0.4 → visible alert banner (+ personal intervention from section 0).
* Camera starts **only after** an explicit consent screen with "אני מסכים" button; refusal → user can still watch without measurement, with an explanation. Video/landmarks never leave the browser — only the score.
